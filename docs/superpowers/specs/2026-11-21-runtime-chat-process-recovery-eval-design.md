# Runtime Chat 跨进程恢复评测设计

## 目标

增加真实模型评测，验证工具结果已写入 SQLite checkpoint 后，Runtime 关闭并在独立 Python 进程中重建时，能否在同一 `session_id` 下恢复回答而不重复执行工具。

## 范围与限制

- 评测继续显式使用 `builtin.runtime-chat`，工具仍只读取 `about.txt` 内存 fixture，真实副作用为 0。
- 一个父脚本启动两个独立 worker 进程：第一个完成工具调用并在下一次模型调用前注入故障；第二个重新创建 Runtime、打开同一 SQLite checkpoint 并重试同一请求。
- API Key 由用户在交互终端隐藏输入，仅由父进程保存在内存中并通过子进程环境传递；不放入命令行参数、报告或临时文件。
- 报告记录两阶段模型用量、Runtime 重建、checkpoint 中已保存的工具结果、工具 handler 总执行次数及最终答复。
- 这验证独立 Runtime/进程边界下的持久化恢复，不模拟操作系统强制终止、断电，也不覆盖工具副作用已发生但结果尚未写入 checkpoint 的未知结果窗口。

## 方法选择

- 两个独立子进程由一个父评测命令协调：可复现真实进程隔离，密钥只输入一次，推荐采用。
- 两次手工命令：实现更简单，但用户要重复输入密钥并自行管理共享状态。
- 同进程关闭再打开 SQLite：成本最低，但不能验证进程边界。

## 验收标准

- 第一进程确认模型故障发生在工具 handler 完成且工具结果持久化之后，并以正常评测状态退出。
- 第二进程以同一 `session_id` 读取旧 checkpoint 并完成回答。
- 两阶段合计恰好一次 `read_text_file(path="about.txt")` handler 执行；第二阶段 handler 执行次数为 0。
- 报告明确标出跨进程恢复验证边界，且不保存 API Key。
