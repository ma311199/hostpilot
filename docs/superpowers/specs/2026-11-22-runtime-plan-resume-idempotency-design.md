# Runtime Plan 持久恢复与工具幂等设计

## 意图

让 Plan 在 Host 重启或进程故障后能够由用户明确恢复，并利用工具调用前持久记录的稳定幂等键安全地恢复未决调用。当前 Runtime 已持久化 Turn/TaskRun 元数据、已完成 Plan 结果和 Runtime Chat 的消息级 Checkpoint，但没有恢复旧 Plan 的 Blackboard、DAG 和执行位置；不确定的副作用工具调用会被阻断并交由用户核实。

## 目标

- 新 Plan 开始后持久化稳定的 `plan_run_id`、已验证的 DAG、任务状态、依赖结果及恢复位置。
- Host 重启后将未终结 Plan 标为 `interrupted`，在用户明确确认前不继续执行。
- 每次工具调用在派发前持久化一个逻辑调用记录及稳定幂等键；持久化失败时禁止派发。
- 区分纯读、带幂等键的写入、非幂等写入和未知调用，采用不同恢复规则。
- 没有该逻辑调用的预写记录时，Runtime 可以确定它没有穿过派发边界；用户确认恢复后可以重新运行。
- 有未决记录且结果未持久化时：纯读调用可重试；声明了幂等键支持的写入使用相同键和相同请求重试；其他调用暂停并要求用户核实。
- 幂等键只用于工具适配器与外部服务，不暴露给模型、不改变工具参数 Schema、不写入 Trace/Audit。
- 恢复调用仍受当前工具授权、Policy、预算及确认门约束。

## 非目标

- 不在未经用户确认时自动恢复 Plan 或派发工具。
- 不为没有幂等保证的服务伪造去重语义，也不把普通重试视为安全恢复。
- 不自动恢复已确认的副作用，也不自动补偿远端业务系统。
- 不要求移除 LangGraph/DeepAgents；它们继续通过 Runtime 管理的接口或适配器提供能力。
- 不改变成功 Plan 结果缓存的精确指纹与人工审批语义。

## 约束

- 稳定幂等键由逻辑操作身份生成，至少包含 `plan_run_id`、任务 ID、任务内调用序号和工具稳定 ID；工具可提供业务标识参与键生成。键不可依赖新的 Turn ID、随机调用 ID 或每次尝试生成的随机值。
- 每条待恢复调用同时绑定规范化请求指纹。恢复时请求指纹不匹配则停止自动重试，防止用旧键提交不同参数。
- 外部工具只有显式声明并实现 Runtime 的幂等能力契约时才可用相同键重试。通用 MCP 协议本身不保证幂等键语义，未扩展的远程工具视为不支持。
- 服务端声明必须说明幂等去重的有效期限和请求体冲突行为；超过有效期限或不能证明同一请求时转人工核实。
- Plan 快照和重放所需的调用参数属于本地 Session 数据：不进入日志、Trace 或 Audit；使用现有 SQLite 文件权限，并随 Session 删除一并清理。当前代码没有数据库加密，设计不宣称静态加密。
- 迁移前已中断的旧 TaskRun 缺少 PlanRun 快照，不能自动恢复；仍使用现有核实/重新发起流程。

## 方法与方案比较

1. **Runtime PlanRun 快照 + 工具调用日志（推荐）**：Runtime Store 持久化整个 Plan 的恢复边界，并在 ToolFacade 派发前写入逐调用日志。用户确认后从快照恢复；Runtime 根据工具能力和日志状态决定执行、幂等重放或人工核实。状态来源明确，工具不会因重建 Plan 而换用新的去重键。
2. **重启后重新生成 Plan 并复用业务键**：不保存完整 DAG 和依赖进度，恢复时让模型重新规划，再尝试复用工具幂等键。模型可能改变任务拆分、参数或调用顺序，无法稳定判断它对应原来的哪个逻辑调用，不能可靠重建 Blackboard，因此不采用。
3. **继续只做人工核实、不保存 Plan 快照**：维持当前安全门，不增加自动恢复能力。实现风险最低，但未满足恢复中断 Plan 的目标，因此不采用。

## 关键行为

### PlanRun 生命周期

- 每个 Plan 生成一次不可变 `plan_run_id`，并保存 Session、原始目标、已验证计划、依赖图、任务输入/输出、状态、下一恢复位置及版本号。
- 任务状态至少区分 `pending`、`running`、`completed`、`failed`、`interrupted`；Host 启动只把过期 Host 持有的运行状态转为 `interrupted`，不自动派发。
- 恢复入口展示原目标、完成任务、待执行任务和待核实调用；用户确认后才创建新的恢复 Turn 并租用该 PlanRun。并发恢复通过 Store 原子认领限制为一个活动恢复者。
- 继续执行时沿用原 `plan_run_id` 和 DAG/任务 ID，但使用新的 RequestContext、预算和当前 Policy/授权。已完成任务结果不再执行；旧策略不构成授权。
- 只有因 Host/进程中断或等待人工核实而暂停的 PlanRun 可恢复。已经正常终结为 `failed` 的 PlanRun 保持终态；用户可以发起新 Plan，由已有历史结果和失败摘要帮助重新规划。

### 工具调用和恢复决策

- 每次工具派发使用一个稳定的逻辑调用 ID，并先在 Runtime invocation store 中以事务写入 `prepared` 记录，再进入 ToolFacade/Provider。派发结果成功且对应 Checkpoint/PlanRun 状态已持久化后标记 `completed`。
- 记录包含 PlanRun/Turn/TaskRun/任务 ID、逻辑调用序号、工具 ID、调用分类、幂等键、规范化参数指纹、状态、创建时间及幂等期限。精确重放所需参数存入 Session checkpoint 数据，不保存到 Trace/Audit。
- Runtime 按以下规则恢复：

  | 调用类别 | 有预写记录且无持久结果 | 无预写记录 |
  | --- | --- | --- |
  | 纯读 | 用户确认恢复后可重试 | 用户确认恢复后可执行 |
  | 幂等写 | 工具声明支持且期限有效时，使用相同幂等键、相同请求指纹重放；服务应返回原结果或安全冲突 | 用户确认恢复后可执行，并先写记录 |
  | 非幂等写 | 仅在工具声明支持且期限有效时使用相同键和请求重放；否则等待用户核实，不派发 | 用户确认恢复后可执行，并先写记录 |
  | 未知类别 | 等待用户核实，不派发 | 用户确认恢复后可执行，并先写记录 |

- 如果工具声明不支持幂等键、其有效期限已过、请求指纹变化，或存储/能力信息不完整，Runtime 失败关闭并要求人工核实。用户可确认“已执行”并提供实际观察到的结果，或确认“未执行”后允许新的工具调用；未核实前 Plan 保持暂停。
- 人工核实由当前 Session 的交互用户作出声明；HostPilot 无法独立验证远端业务系统状态。用户选择“已执行”时必须提供实际观察到的原始结果文本，系统以 `user_reported` 标记后作为该工具结果交给后续步骤；选择“未执行”时不伪造结果，恢复时才重新派发。若用户无法提供执行结果，则保持暂停，不能把空结果当成功。
- 非幂等副作用不能靠一次新的随机键安全重试。凡要自动恢复一次逻辑写操作，工具端必须保证同一幂等键去重，并拒绝键相同但请求体不同的调用。
- 当前 MCP 没有统一的幂等执行语义。内置/定制 Provider 可实现 Runtime IdempotentTool Port；未显式接入该 Port 的远端 MCP 和 STDIO 工具按不支持处理。

### 副作用与重试分类

- `pure_read`：没有外部状态副作用，可重试。
- `idempotent_write`：带工具端支持的幂等键，重复同一逻辑请求不会重复产生效果。
- `non_idempotent_write`：重复可能重复发送、扣款或触发审批；有工具端幂等契约时才允许同键重放，否则人工核实。
- `unknown`：按非幂等写处理。
- 影响等级、可逆性和审批要求仍作为独立治理维度；例如可补偿写入不自动等于可安全重试。

## 代码边界

- `hostpilot.runtime`：定义 PlanRun/ToolInvocation 状态模型、恢复决策与 IdempotentTool Port。
- `TaskStore`/SQLite 持久化：保存版本化 PlanRun 快照、任务状态和逐调用日志；为 Session 删除增加一致性清理。
- `RuntimeContext`/Host 生命周期：恢复过期 Host 的 PlanRun 状态、认领唯一恢复者，并在关闭时记录中断位置。
- `ToolDescriptor`、ToolFacade 与 Provider 适配器：声明副作用/幂等能力，按声明传递 Runtime 生成的稳定键；默认通用 MCP 不声明幂等支持。
- `OrchestratorPlanExecutor`：在计划验证、任务 wave 和 Blackboard 状态变化时持久化快照；从中断快照重建状态并从安全位置继续。
- Chat API 与 Vue 会话界面：列出可恢复 Plan、展示已完成/待执行/待核实项，并要求用户明确恢复或核实。
- Trace/Audit 继续只记安全 ID、状态和原因码；不写工具参数、幂等键或结果正文。

## 验证

- SQLite 关闭/重开和多 Host 测试覆盖 PlanRun 快照、版本迁移、唯一恢复认领、Session 删除和 Host lease 过期。
- 故障注入覆盖预写入前失败（确认无派发）、预写入后/派发前崩溃、外部副作用后/结果写入前崩溃、结果 Checkpoint 后崩溃。
- 工具分类测试覆盖纯读重试、同键同请求返回原结果、同键不同请求拒绝、幂等期限过期、缺失支持声明转人工、非幂等工具不会自动重放。
- 集成测试覆盖用户确认前零恢复派发、确认后恢复依赖 wave、已完成步骤不重复执行、未决调用阻断后续步骤、预算/Policy/确认门在恢复时仍执行。
- API/UI 测试覆盖中断 Plan 展示、恢复确认、已执行/未执行结果核实及暂停/失败反馈。
- `failed` 终态不出现在可恢复列表；仅 `interrupted` 与等待人工核实的 PlanRun 可以恢复。
- 不用真实模型评测替代工具幂等和持久化故障注入；真实模型质量评测由用户按现有流程手动运行。

## 需要产品确认的实现限制

通用远程 MCP/STDIO Server 不提供 HostPilot 可验证的幂等保证时，系统无法自动重试其未决写操作。此类调用只能等待用户核实，或由对应 Provider/Server 显式实现并声明 HostPilot 幂等能力契约。SQLite 会保存恢复需要的任务快照和待重放参数，数据遵循本机数据库现有的权限和 Session 删除边界，但不具备静态加密。
