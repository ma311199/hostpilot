# Runtime Plan 子任务缓存与人工确认设计

## 意图

在同一 Session 的后续 Turn 中，精准识别此前成功完成的相同 Plan 子任务，避免重复消耗模型与工具调用；复用结果前由用户明确决定。历史失败记录作为规划参考，帮助 Planner 避免重复已知失败路径。

## 已决定的行为

- 所有成功结果命中都要求人工选择，不按只读/有副作用分流，也不做数据源版本探测。
- 每个命中都展示历史任务说明、完成时间和成功输出；用户选择“复用并跳过”或“忽略结果并执行”。没有用户决定时不复用，也不自动执行该命中任务。
- 命中结果经用户选择复用后，作为当前 Plan 的已完成 TaskState 提供给依赖任务；写入 Trace，记录缓存来源与用户决定，不把结果正文写进 Trace/Audit。
- 只有任务定义、显式输入、预期输出、Skill/执行类型和已解析依赖结果完全匹配，才是缓存候选。Session 隔离；缓存内容是否仍符合外部世界由人工选择承担。
- 失败任务不进入成功缓存。保存受限失败摘要（任务说明、稳定错误码、是否出现副作用、指纹；不包含任务输入），供新 Turn Planner 参考；不保存失败输出或原始异常，不自动重试。

## 方案

1. **把最近成功结果都注入 Planner（现状的延伸）**：实现简单，但会消耗上下文且不能精确匹配当前任务。
2. **按确定性任务指纹逐任务查找，并对每个成功命中请求人工决定（选用）**：Planner 只获得有界失败摘要；当前 Plan 执行到每个任务时，Runtime 按指纹检索成功结果，命中后通过专用 WebSocket 交互显示结果并等待“复用”或“执行”选择。这个方式限制上下文并确保每次跳过都有用户决定。
3. **要求工具报告数据源版本并据此自动复用**：能减少审批，但需要每个文件/外部工具支持版本或内容哈希；当前工具接口不具备统一版本契约，且用户选择了统一人工审批，因此暂不采用。

## 匹配与存储

- 任务指纹使用版本化 SHA-256，输入包含 execution type、skill ID、规范化 description、expected output、规范化显式 input，以及依赖 ID 与对应规范化输出的映射。当前任务自身的 `task_id` 不作为匹配依据，依赖 ID 用来保留依赖输出的来源关系。
- SQLite `TaskStore` 保存成功结果及指纹；结果查询只返回当前 Session 的精确指纹候选。已有最多 65,536 字节的单项结果上限保留。
- 失败摘要保存独立于成功结果，最多向 Planner 提供同 Session 最近 16 条、总计不超过 16,384 字节。只包含任务说明、稳定错误码和副作用计数；失败输出、原始异常、任务输入、工具参数和凭证不进入 Planner 摘要。持久化输入字段保持空对象以兼容统一存储模型。
- 缓存复用不会创建实际执行型 TaskRun；Trace 记录 `cache_candidate`、`cache_reused` 或 `cache_ignored`、source TaskRun ID、当前 task ID 和选择。Runtime 不记录结果正文。

## 人工交互

- 增加专用 WebSocket 消息：Runtime 发送 `plan.task.cache.request`，其中包括 request ID、任务说明、来源 Turn、时间和成功结果；前端展示结果及两个明确操作：“复用并跳过”和“忽略并执行”。
- 前端以 `plan.task.cache.decision` 回复 `reuse` 或 `execute`。没有 WebSocket/provider、等待取消或连接中断时，不复用；当前 Turn 按现有取消边界收尾，不把默认值解释为同意。
- 多个候选命中按 Plan 拓扑顺序逐项确认，避免并行审批窗口混淆。后续依赖在决定后读取已复用或新执行的状态。
- 复用与忽略都写入现有 Trace；用户可在 Trace 页面按请求查看任务命中及选择。Trace 仅存允许列表中的 ID、状态和选择，不存结果正文。

## 失败参考

- 只把状态为 `failed` 且带稳定错误码的历史任务作为 Planner 参考，不当作已完成状态或缓存候选。
- Planner 被要求把失败信息用于调整策略、澄清缺少的信息或说明重试依据；历史失败本身不会触发工具/Skill 重放。
- `cancelled`、`interrupted`、不确定副作用任务不作为普通失败参考；沿用现有工具结果不确定门禁和人工核实流程。

## 非目标

- 自动复用任何成功结果。
- 对任意工具自动判定外部数据是否变化。
- 恢复旧 Plan DAG/游标，重试失败任务，或重放未决副作用。
- 将任务输出或失败原文写进 Trace/Audit。
- 增加独立缓存管理页面或结果编辑界面。

## 验收

- 不同 Session、不同任务定义、不同输入、不同依赖输出不会命中同一结果。
- 相同成功任务命中后先展示结果并等待人工选择；`reuse` 才跳过执行并向后续依赖提供输出；`execute` 才调用 TaskExecutor。
- 无审批提供方、取消或断连时，绝不默认复用。
- 每个命中和选择可在 Trace 中查到，Trace 不含缓存正文。
- 失败摘要能跨应用重启被 Planner 读取，且不包含失败输出/异常文本，不自动导致重试。
- 全量 Python、前端单测与构建、Ruff、mypy、格式和差异检查通过。
