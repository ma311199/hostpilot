## 开发亮点与核心内容

1. **读写工具进入统一治理链。** Router 命令、Agent 发起的 MCP 工具调用最终均由 Tool Provider 交给 Tool Executor，沿用参数校验、策略授权、预算、超时、结果验证与审计边界。
2. **把副作用审批放在执行前。** 写文件先通过策略，再由 WebSocket 请求用户确认；批准才执行。拒绝、取消、超时或连接断开都会 fail-closed。HTTP 调用没有交互审批，因此不会执行高影响写入。
3. **审批摘要不泄露正文。** 前端收到工具名、request_id 和安全摘要，不收到待写入文件内容；审批决定只接受与当前 request_id 匹配的消息。
4. **本地文件工具限制清晰。** 工具以进程启动工作目录为根，仅接受 UTF-8 文本并限制大小；拒绝绝对路径、路径穿越、符号链接和不存在的父目录。
5. **前后端审批协议可独立验证。** `tool.confirmation.request` / `tool.confirmation.decision` 在 FastAPI WebSocket、前端客户端和审批弹窗间形成一条闭环，并覆盖 request_id 匹配和等待时限。

## 已完成的工程改进

- 将高影响调用使用的确认 Provider 显式放入每次 Agent runtime 调用上下文，避免依赖全局状态，也使同一请求中的 MCP 拦截器能够获得正确的 WebSocket 决定通道。
- 将工具权限边界收敛到同一工作区根路径，拒绝路径解析后的越界位置、符号链接和缺失父目录，缩小文件工具可触达范围。
- 审批摘要只包含用户确认所需的信息；文件正文不进入审批事件，避免在 UI 消息和协议日志中重复传播敏感内容。
- 对 WebSocket 审批等待设置 60 秒上限，并将断线作为取消处理，避免等待连接的请求无限挂起。
- 为无法交互审批的 HTTP 入口保留 fail-closed 行为，不通过跳过确认来复用高影响工具。
- 用端到端测试验证浏览器收到审批请求、提交匹配决定并得到聊天响应；前端 lint 自动修正了审批弹窗模板格式。

本轮没有进行性能优化或基准测试；以上改进集中在安全边界、状态传递、故障收敛和协议可验证性。

## 验证结果

- 全量后端测试：114 passed。
- Ruff lint 与格式检查通过。
- 前端 lint、类型检查和生产构建通过。
- 未采集覆盖率，不报告覆盖率百分比。
- FastMCP 依赖产生一条 Authlib 弃用警告，测试通过且警告不影响功能验证。
