- 记录日期：2026-10-30

- 关联验证：[SQLite 与 Markdown 持久化验证记录](../test-results/2026-10-29-session-persistence.md)
- 关联决策：[ADR-0004：FastAPI 后端接口与前后端边界](../decisions/0004-fastapi-backend-api.md)、[ADR-0005：SQLite 会话检查点与 Markdown 记忆](../decisions/0005-sqlite-checkpoints-and-markdown-memory.md)

## 开发亮点

1. **先明确运行边界，再实现接口。** 项目需求确定为单终端、单本地用户、免登录、多会话；API 默认监听 loopback，前端跨源调用需要显式配置 CORS 来源。
2. **持久化按职责分工。** SQLite 保存会话目录和 LangGraph 检查点；Markdown 保存会话摘要与共享长期记忆。conversation_id 映射为 thread_id，使每个会话有独立的图状态。
3. **核心领域契约与框架适配隔离。** Pydantic 契约不依赖 FastAPI 类型；DeepAgents 适配器只在调用方传入时注入 checkpointer。
4. **本地数据采用最小权限和安全写入。** SQLite 数据库与目录、Markdown 文件与目录设置本地权限；Markdown 使用临时文件和原子替换，并限制路径、符号链接和文件大小。
5. **将恢复与隔离纳入自动验证。** 测试覆盖关闭并重新打开 SQLite 后恢复图状态、不同会话互不串线、记忆文件隔离、API 会话删除及本地 CORS 配置。
6. **把质量检查做成可复用入口。** scripts/check_quality.sh 统一运行格式检查、lint、mypy、pytest 和锁文件一致性检查；后续 CI 可调用该脚本。

## 已完成的实现优化

- ContextBuilder、消息提交/历史 API 和可注入 AgentRuntime 已形成首版垂直切片；没有把未选定的模型供应商写入核心服务。
- 模型接入通过 `langchain-openai` 的 OpenAI 兼容边界装配，模型标识、密钥和可选 Base URL 使用环境变量；未配置模型时保留明确的 503 行为。实际供应商连通性仍待用户提供配置后验证。
- 免登录 API 对带 Origin 的写请求执行本机同源或配置来源校验，拒绝其他来源。

- 会话标识采用 UUID 校验，并统一用作 LangGraph thread ID，避免路径输入和线程映射不一致。
- SQLite 使用 user_version 记录首版 schema，拒绝由更新版本程序创建的数据库，避免旧代码误写新 schema。
- SQLite 会话元数据和 LangGraph 检查点共用本地数据库文件，减少独立数据库及状态同步工作。
- Markdown 写入限制内容大小，拒绝符号链接和越界路径，并用原子替换降低写入中断造成的半文件风险。
- 本地 API 主机配置限定为 loopback 地址；CORS 来源使用显式配置，不启用凭证跨源传递。
- 根据验证发现修正了预算耗尽边界、日志类型、数据库 schema 检查和文件权限处理顺序。

## 验证结果

2026-10-30 首轮 Phase 0 完整质量检查记录为：53 项测试通过；Ruff 格式和 lint 检查通过；mypy 检查 39 个源文件无问题；uv lock --check 解析 113 个锁定包并通过。模型运行时接入后为 57 项测试通过；2026-10-31 加入记忆写入服务后为 61 项测试通过、Ruff 检查 55 个文件格式正确、39 个源文件类型检查通过，依赖锁解析 117 个包。模型工厂自动化测试使用替身；真实供应商的对话、重启续聊及会话隔离由用户终端冒烟验证通过。未采集覆盖率，因此不报告覆盖率百分比。

| 优先级 | 优化项 | 原因与验收建议 |
| --- | --- | --- |
| P1 | 配置并验证真实模型服务 | OpenAI 兼容运行时装配已完成；需配置实际供应商和模型，并验证真实回答、重启续聊和供应商错误处理。 |
| P1 | 接入受策略控制的 Markdown 记忆写入 | MemoryWriteProposal、显式批准门、范围 / 会话校验与大小限制已有应用层首版；后续需接入待审批 API / UI 流程及模型提案来源，并验证拒绝后无文件副作用。 |
| P1 | 扩展无登录 API 的请求来源保护 | 当前带 Origin 的写请求会校验本机同源或配置来源，无 Origin 的本机客户端调用仍允许。接入工具副作用后，需复核非浏览器调用边界并为高影响操作继续执行策略与用户确认。 |
| P1 | 建立 CI 流水线和覆盖率基线 | 本地质量脚本已存在，CI 平台仍未确定；尚未采集覆盖率。选定平台后接入脚本，并按会话隔离、策略拒绝和持久化恢复等关键模块查看覆盖。 |
| P2 | 完善 SQLite 迁移、备份与并发配置 | 当前 schema 只有首版版本号保护，尚无迁移和备份流程；也未为并发写入配置专门的 WAL、busy timeout 或负载基线。根据本地并发与恢复目标建立迁移和备份验证。 |
| P2 | 处理会话删除的跨存储一致性 | 删除目前依次清理 checkpoint、会话索引和摘要；进程中断可能留下孤立数据。可增加可重试的删除状态标记或启动时一致性扫描，并测试每个中断点。 |
| P2 | 定义长期记忆合并和冲突策略 | 共享 Markdown 当前采用整文件替换，适合首版单进程写入；未来需要并发编辑时应增加版本校验、锁或分段文件策略，防止互相覆盖。 |
| P2 | 接入真实 Trace、Cost 与 Audit 导出 | 当前已有事件和 Protocol，尚无持久化或外部导出适配器；主流程接入前应明确审计保留策略并验证敏感字段不落日志。 |
