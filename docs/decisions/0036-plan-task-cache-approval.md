# ADR-0036: Plan 子任务成功结果复用必须逐项审批

- 状态：已接受
- 日期：2026-11-22

## 背景

Plan TaskStore 已跨 Turn 保存成功子任务结果。若将结果成批交给 Planner，既会扩大上下文，也会让外部数据变更后的旧结果被误用。只读任务同样可能依赖已变化的数据源，因此无法仅凭工具类别安全地自动复用。

## 决策

1. 成功结果按版本化 SHA-256 指纹匹配。指纹包括执行类型、Skill、规范化任务说明、预期输出、显式输入和已解析依赖 ID 与对应输出。查询限定在同一 Session，并排除当前 Turn。
2. 每个候选必须向用户展示历史结果、来源 Turn 和完成时间。只有用户明确选择“复用并跳过”才把该输出写入当前 Blackboard；选择“忽略并执行”会调用普通 Task Executor。
3. 没有审批 Provider 或等待超时会澄清并停止当前 Turn，不复用也不执行命中任务；连接中断会取消等待中的 Turn。审批不判断或探测数据源是否变化，用户根据展示内容承担复用判断。
4. Trace 记录候选来源、任务 ID 和选择，不记录结果正文。缓存命中不创建假的实际执行 TaskRun。
5. 失败任务保存在独立有界摘要中，提供稳定错误码、任务说明和副作用计数给后续 Planner；不保存失败输出或原始异常，不自动重试。失败摘要不是已完成任务，也不能作为成功缓存复用。

## 后果

- 所有命中都需要人工操作，包括只读任务；可避免重复执行和上下文膨胀，但增加用户交互成本。
- 精确指纹减少不相关候选。依赖输出变化会改变下游任务指纹。
- 缓存审批仅跳过 Plan 子任务；它不改变工具本身的授权、Policy 或高影响写入确认要求。
- 用户取消、拒绝复用、审批超时或审批通道不可用都不会造成缓存跳过或自动执行命中任务。
