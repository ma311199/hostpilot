# ADR-0037: 成功子任务缓存保存安全执行摘要

- 状态：已接受
- 日期：2026-11-22

## 背景

Plan 子任务成功结果可跨 Turn 提交人工审批，以决定复用历史输出或重新执行。只有结果正文和任务说明时，用户无法判断历史任务实际调用了哪些工具、工具影响等级如何、是否经过人工确认。

## 决策

1. 成功结果可附带 `execution_summary`，只保存工具 ID、聚合调用次数、影响等级，以及当前子任务观察到的确认决策枚举。
2. 摘要不保存原始工具参数、工具输出、凭证、幂等键、补偿令牌或自由文本确认摘要。允许的影响等级为 `read_only`、`idempotent`、`reversible`、`irreversible` 和 `unknown`。
3. 只计入成功返回的工具调用。明确声明为只读的工具显示 `read_only`；工具描述只表示“可能有副作用”且未声明更具体等级时显示 `unknown`，不把“可能有副作用”推断为“不可逆”。业务 Skill 可使用执行期间记录的具体效果等级。重复工具调用按工具 ID 聚合。
4. 执行摘要与成功输出及 TaskRun terminal state 在同一 SQLite 事务提交；单结果大小仍受 65,536 字节限制。旧结果通过可空字段迁移，界面明确显示“执行摘要不可用”。
5. 缓存审批同时展示摘要和结果。复用会跳过历史调用；重新执行会再次运行子任务，可能重复产生副作用，并继续经过当前 Policy 和人工确认门。
6. Task Trace 可以记录同样的工具 ID/次数/影响等级和确认决策，但不记录参数、工具结果或子任务输出。

## 后果

- 用户可以在选择复用或重新执行前看到历史工具调用和影响等级；不完整或旧数据保持明确未知。
- 摘要是辅助判断信息，不能证明外部数据仍未变化，也不能保证工具提供的影响元数据正确。
- 单条摘要和历史列表均受已有结果字节预算约束，避免审计元数据导致无界增长。
