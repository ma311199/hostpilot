# ADR-0032：上下文指代候选解析

- 状态：已采纳
- 日期：2026-11-14
- 相关：[ADR-0028](0028-hybrid-memory-recall.md)、[ADR-0031](0031-hybrid-skill-routing-and-local-vector-index.md)

## 背景

`resolve_query()` 原先只对最近对话和摘要做确定性指代解析，不检查长期记忆；“这段内容”等短语也未全部识别。无显式路径或引用时，材料可能在记忆中存在，但路由无法把它与本轮请求联系起来。反过来，直接让分类模型自由补充上下文会产生记忆内容幻觉风险。

## 决定

- 对需要上下文的指代，候选只从最近用户/助手消息、会话摘要和本轮已装配的长期记忆中构造，并限制候选数量与每项长度。
- 单一明确路径或引用仍由确定性规则解析。其他语义指代先调用当前路由 Provider，并使用同一请求预算。
- 模型只能返回候选 ID、置信度和原因码，或返回无匹配；HostPilot 校验 ID 必须属于本次候选集合。只有置信度不低于 `0.80` 才把选中候选加入 Skill 检索文本。
- 无候选、无匹配、候选 ID 非法、低置信、模型不可用或预算耗尽时，直接走 `builtin/clarify`，不启动 Skill 检索。
- 对话与记忆作为不可信数据输入模型。Trace 记录解析状态、候选编号、数量、来源和置信度，不记录候选正文。
- route-only 评测默认清除共享记忆；专用评测可注入有大小上限且不持久化的合成上下文，以真实模型检查匹配和澄清行为。

## 影响

- 有相关记忆时，“把这段内容整理一下”可以根据明确候选继续路由；无相关材料时会在 Skill 检索前澄清。
- 需要语义消歧的请求增加一次受预算约束的模型调用；唯一明确引用不增加模型调用。
- 模型无法确认候选时会要求用户补充，避免任意选择记忆或由模型编造内容。

## 复核条件

新增记忆召回后，检查候选召回是否覆盖需引用的材料，并用无匹配、多候选、低置信和跨轮指代样例评估误选率。若 `0.80` 置信门槛不适配所用模型，应通过标注评测集校准后修订。
