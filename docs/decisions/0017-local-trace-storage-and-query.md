# ADR-0017：本地 Trace 元数据持久化与查询

- 状态：已采纳并实现首版
- 日期：2026-11-07
- 关联：[新架构文档](../新架构文档.md)、[需求基线](../requirements.md)、[前端架构](../frontend-architecture.md)、[测试策略](../testing-strategy.md)

## 背景

HostPilot 已定义 Trace 事件契约，记忆控制器会生成脱敏事件，聊天服务也能关联路由结果与 Token 用量；此前 Trace 只写入结构化日志，没有本地查询 API 或观测页面。

## 决定

- Trace 元数据存入现有本地 SQLite 数据库，不额外引入日志数据库或遥测服务。
- Trace Store 只持久化 `status`、`reason_code`、计数、耗时、`skill_id`、`tool_id`、执行入口、路由和 Token 数等明确允许的字段。未列入白名单的属性直接丢弃。
- Trace 按 `trace_id` 关联请求事件；本地 API 提供最近请求列表和单个请求的事件详情，页面不展示对话正文、记忆内容、工具参数或凭证。
- 数据最多保留 30 天、最多 100,000 个事件；SQLite 数据目录和数据库文件分别限制为当前用户可访问。
- 跟踪聊天完成路由/用量、记忆召回、Skill 执行、工具调用与审批事件。Span 使用 `parent_span_id` 关联请求、Skill、工具和审批层级；新增事件仍须先定义安全元数据字段。

## 影响

- Trace Sink 故障不能改变已经完成的聊天响应或记忆访问结果。
- SQLite 提供本地、无需额外服务的观测数据；这不是多进程集中式或远程遥测方案。
- 当前未持久化独立 Cost/Audit 事件，也不记录模型内部推理步骤；Trace 页面展示已记录 Span 的父级关联。

## 验证

- 验证同一 `trace_id` 下的聊天与记忆事件聚合、时间顺序、白名单过滤、事件数量上限及详情查询。
- 验证 HTTP API 对不存在的 Trace 返回 404，页面处理列表、详情、空状态与服务错误。
- 验证对话正文和未允许属性不会出现在 SQLite 查询结果或 API 响应中。
