# 记忆重要性分层写入验证

## 实现

- 增加本地、确定性记忆评分规则及低／中／高三级结果：0–39 低分、40–74 中分、75–100 高分。
- 低分提案不进入审批队列、不写入记忆或归档，并留下不含正文的审计原因码；中、高分仍须显式审批。
- 中分批准后写入最多 800 字符的抽取式摘要及原文归档；高分批准后写入原文。
- 原文归档总量上限为 500，目录权限为 0700、归档文件权限为 0600；列表只返回共享长期归档和当前会话归档。
- 验证归档容量耗尽时批准失败、提案留在待处理队列，且现有摘要和归档不被覆盖。
- 新增 ADR-0027，并同步新架构、开发指南和路线图中的策略说明。

## 验证

- 全量后端测试：349 passed，1 条第三方 Authlib 弃用警告。
- Ruff：`src/hostpilot` 与 `tests` 检查通过。
- MyPy：91 个后端源文件检查通过。
- 前端 Vitest：17 个测试文件、66 项测试通过。
- `git diff --check`：通过。
- 未采集覆盖率。

## 限制

- 评分是词项与长度规则构成的启发式，不具备语义理解能力，且凭证识别不能覆盖所有秘密格式。
- 中分摘要为抽取式，需使用用户认可的记忆样例校准规则、阈值和摘要效果。
- 归档达到上限后不会自动清理或覆盖旧记录；需由后续生命周期策略处理。
