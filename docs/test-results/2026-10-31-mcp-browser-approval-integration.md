# MCP 与浏览器审批自动化联调验证

- 日期：2026-10-31
- 范围：聊天 WebSocket、MCPToolProvider、ToolExecutor、工作区文件工具和 Vue 审批交互

## 实现与验证

- 自动化集成测试通过真实 MCP Provider 和 Tool Executor 发起工作区文件写入，并由聊天 WebSocket 的确认 Provider 等待决定。
- 批准后文件写入成功；拒绝、取消及审批等待超时均返回明确失败状态，且目标文件不存在。
- 聊天 WebSocket 使用独立错误码区分用户拒绝、用户取消和审批超时；前端显示对应说明，不再误报为策略或预算拒绝。
- 审批摘要不包含文件正文。Vue 审批窗口提供批准、拒绝和取消操作；前端测试覆盖拒绝、取消，状态看板测试覆盖断线后重连。
- 聊天历史只呈现有内容的用户消息和助手最终回复；空的模型工具调用消息及 MCP 工具结果不再重复显示为助手答复。
- 集成测试使用确定性 AgentRuntime 替身，不访问真实模型服务；它验证了 MCP 执行与用户审批边界，但不验证真实模型是否会发出预期工具调用。
- 用户随后报告已配置模型并完成本机手动联调：模型发起写入工具调用，浏览器展示审批；批准后文件内容正确写入，拒绝后没有文件副作用。

## 聊天历史显示回归修复

真实审批试用发现，历史 API 中的空 AI 工具调用和 MCP `tool` 结果被聊天面板当作普通回复呈现。前端现仅显示有内容的用户消息和助手消息，回归测试覆盖工具调用/工具结果/最终回复并存的历史记录。

用户拒绝审批时 Agent turn 会结束，因此页面不会再收到模型生成的助手回复；前端会明确提示“你已拒绝此操作，文件未更改”。
