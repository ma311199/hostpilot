# Stage E：Harness 运行时配置验证

## 范围

首版配置页仅管理当前执行链已有支持的八项：上下文历史条数、记忆字符上限、请求/响应字符上限、Token/工具/知识检索预算和单请求超时。配置存入本地 SQLite；应用启动时恢复，在线更新通过与聊天请求共享的运行时锁即时作用于后续请求。模型和 MCP 连接仍由各自页面管理。

页面未暴露重试、Agent 循环次数、工具白/黑名单、Skill 运行策略或沙箱开关，因为当前没有对应运行机制。配置模型拒绝未知字段并限制字符、次数和超时范围。SQLite 初始化会创建私有目录、拒绝符号链接并将数据库权限限制为当前用户读写。

- 后端全量：`pytest -q`，280 项通过。
- Harness SQLite 存储定向覆盖：4 项通过，`harness_configuration.py` 行覆盖率 100%。
- 前端全量：13 个测试文件、50 项通过。
- 前端：ESLint、TypeScript 类型检查与生产构建通过。
- 后端：Ruff 检查与格式检查通过。
- 运行测试时出现第三方 `AuthlibDeprecationWarning`，不影响测试结果。

## 结果分析

覆盖启动配置恢复、在线预算/上下文/请求大小应用、跨重启读取、越界配置拒绝、数据库与父目录符号链接拒绝，以及配置页加载、保存、错误态和导航。配置写入与请求执行共用锁，避免单次请求中途切换预算或上下文限制。当前没有端到端浏览器自动化覆盖真实浏览器启动流程；页面行为由 Vue 组件测试和类型检查验证。
