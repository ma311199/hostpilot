# Linux Python 沙箱首轮验证

## 实现范围

- 增加经用户审批后调用的 `run_python_code` 内置工具。
- Linux 使用 bubblewrap 建立无网络、无宿主工作区挂载的命名空间，并清理继承环境变量。
- 使用 `prlimit` 和运行时限制约束 CPU、地址空间、进程数、墙钟时间、源码大小及输出大小。
- 工具目录状态通过一次无害隔离探针确认 bubblewrap 命名空间和 Python 运行时能否启动；探针结果在该实例内缓存。真实调用仍独立建立沙箱，启动异常时不回退到宿主执行。
- 审批拒绝、取消和超时的聊天提示使用通用操作文案，适用于代码执行及文件类工具。
- 仅支持 Linux。STDIO MCP 子进程、进程内插件、远程 MCP 和 Windows 不在此隔离范围。

## 验证结果

- 后端完整测试：359 项通过。
- 前端完整测试：17 个文件、67 项通过。
- Playwright 审批 E2E：2 项通过，覆盖文件工具审批往返，以及 Python 沙箱拒绝/批准后的执行行为。
- mypy：93 个源文件通过。
- Ruff：沙箱实现及测试通过。
- ESLint 与 Vue TypeScript 类型检查通过。
- `git diff --check` 通过。
- Linux 沙箱集成用例验证宿主工作区与 `/etc/passwd` 不可见、网络连接失败、进程派生受限、输出上限及墙钟超时。

## 限制

命名空间隔离不等价于虚拟机或硬件隔离，也不约束同一操作系统用户启动的其他程序。系统 Python 运行时目录以只读形式挂载，这是执行代码所需的依赖。实际隔离强度依赖宿主 Linux 内核、bubblewrap 和运行环境配置；预检不替代每次启动时的错误处理。
