# 混合记忆召回离线评测补充

## 范围

- 使用 `docs/evaluations/memory-retrieval-v1.yaml` 的 9 条合成查询和 220 字符预算。
- 新增评估生产策略：先注入 BM25 词项命中的片段，再按会话摘要优先、共享长期记忆其次补入未命中的片段。
- 与固定顺序基线、仅 BM25 命中候选排序比较 Recall@budget、MRR 和平均返回片段数。
- 可复现命令：`.venv/bin/python scripts/evaluate_memory_retrieval.py --char-budget 220`。
- 评测未读取用户记忆文件、调用模型或修改持久数据。

## 结果

| 策略 | Recall@budget | MRR@budget | 平均返回片段 |
| :--- | ---: | ---: | ---: |
| 固定顺序 | 66.7% | 0.291 | 5.00 |
| BM25 命中项 | 88.9% | 0.722 | 1.89 |
| BM25 命中优先 + 固定顺序回退 | 100.0% | 0.759 | 4.67 |

同义改写样例未产生 BM25 命中。混合策略在本预算下按固定顺序补回目标，恢复该样例的覆盖；该结果来自回退内容，不能视作语义检索能力。回退也使平均上下文片段数从 1.89 增至 4.67，接近固定顺序基线。

## 验证

- 检索评测单测：6 passed；覆盖预算限制、会话隔离、BM25 无命中时回退行为。
- 全量后端测试：351 passed，1 条第三方 Authlib 弃用警告。
- 前端 Vitest：17 个测试文件、66 项通过。
- Ruff 检查 `src/hostpilot`、`tests`、`scripts` 通过；MyPy 检查 92 个后端源文件通过；`git diff --check` 通过。

## 限制

- 样本量小且完全合成，指标不代表真实记忆质量。
- 词项不匹配时仍只能回退固定顺序，超出预算的目标可能继续漏召回。
- 后续应使用经用户认可的样例评估摘要、去重、词项排序和可选语义检索，不据此引入向量数据库。
