# 会话级沙箱权限阶梯验证

## 实现范围

- 每个会话在 SQLite 中持久化 `sandbox_mode`；新会话和旧数据库迁移出的会话均为 `read-only`。
- 用户在聊天侧栏明确确认后可升级到更高权限。API 原子校验级别顺序，拒绝重复升级和降级；`read-only` 可直接升至 `danger-full-access`。
- 聊天请求按 `conversation_id` 加载权限，并将其绑定到本次文件工具执行。会话权限互相隔离，请求结束后清除运行期权限状态。
- `read-only` 禁止本会话文件写入；`workspace-write` 允许在应用全局选定工作区内写入；`danger-full-access` 允许内置文件工具访问当前 OS 用户可访问的任意路径。
- 工作区文件操作仍受进程 OS 权限、文件大小限制和高影响操作逐次审批约束。MCP Server、shell、网络及不可信代码沙箱不由这三级模式授权。
- 审计记录允许/拒绝的级别转换，不写入对话正文或文件内容。SQLite 旧会话迁移到只读。

## 验证结果

- 后端测试：320 项通过，0 项失败；第三方 Authlib 有 1 条弃用警告。
- Ruff 检查通过；MyPy 检查 85 个源文件，无问题。
- 前端测试：66 项通过；ESLint、TypeScript 类型检查和生产构建通过。
- 定向集成覆盖会话间权限隔离、用户审批、不可降级、SQLite 重启恢复、旧数据迁移、只读写入拒绝、工作区边界和完全访问路径。

## 已知边界

- `danger-full-access` 当前作用于已注册的内置文本文件工具，不启用 shell、任意网络访问或远程 MCP 权限。
- 操作系统权限仍是最终边界；HostPilot 不提权，也不更改文件权限。
- 真实桌面 UI 的人工操作未做浏览器 E2E；升级流程由前端单测和 API/工具集成测试覆盖。
